# M4 — a real terminal, an honest catalog, and keys that make sense

*Status: planned 2026-07-26, not built. Written after device testing found six
problems in v0.7.0.*

## What the evidence says

Two things were measured before planning anything, because both change the design.

**1. A CGO-free Go binary can allocate a PTY on Android.** Tested on the target phone
in an app-style SELinux domain: `/dev/ptmx` opens, `TIOCSPTLCK`/`TIOCGPTN` succeed,
`/dev/pts/N` opens, `TIOCSWINSZ` sets the window size, and the child process reports
`STDIN IS A TTY`. **No cgo, no JNI, no ttyd, no extra native binary.** The engine we
already ship can host a real terminal session.

**2. The OpenCode install was never broken.** A clean re-install reproduced exactly what
a user sees: the stack finishes correctly (`opencode 1.18.5`) *and* prints
`npm ERR! Exit handler never called!` on the way. npm's known proot quirk (field note 5)
makes a success look like a failure. The bug is the output, not the install.

## The six problems, and what each needs

### 1. After creating a machine, offer plain Linux

Right now the app funnels toward the catalog. It should be equally easy to say "just give
me the machine". After a create completes, the success state offers **Open terminal** as
the primary action, with the catalog as the alternative. The terminal (below) makes this
a real answer rather than a consolation prize.

### 2. The catalog's green ticks are misleading

Every stack shows ✓ because every stack is `verified`, which reads as *installed*. Two
different facts are being conflated:

- **verified** — we ran this on a real phone (a property of the stack)
- **installed** — this machine has it right now (a property of the machine)

The second is what a user wants to see, and the app currently cannot answer it. Plan:

- stack metadata gains `check` (e.g. `command -v opencode`), and the engine grows
  `cellar installed <machine> --json` returning which stacks are present
- cards show **installed / not installed** for the selected machine, with actions
  *Install* → *Open terminal* / *Reinstall*
- `verified` stops being a per-card tick; only *unverified* stacks are marked, as a
  warning. Absence of a warning is the good news.

### 3. Installs look like they failed

Catalog stacks must be quiet on success and loud only on real failure:

- send package-manager noise to a log file inside the machine
- print our own progress (`installing…`, `fetching the binary (~180 MB)…`)
- on failure, exit non-zero and print the tail of that log
- the app reports a verdict from the exit code — "installed" or "failed", never a wall
  of red text that means nothing

OpenCode's stack in particular must say the 180 MB download is expected and slow.

### 4. The activity log grows without bound

The strip expands to whatever the log is. Fix: fixed max height with its own scroll,
collapsed by default, newest line pinned — the whole point of it was to *stop* taking
over the screen.

### 5. The terminal — the main issue

A command box with a fullscreen output pane is still a chat box with a monospace font.
The goal is what Termux and Termius are: **a persistent shell you type into**.

**Architecture (settled by the PTY result):**

```
Compose screen
  └─ WebView (offline, no network)
       └─ xterm.js 6.0.0  (MIT, zero deps, vendored into assets)
            ▲ writes output          ▼ onData(keystrokes)
       JavascriptInterface  ◄──────────────────►  Kotlin
                                   │ stdin/stdout
                                   ▼
       libcellar.so  attach <machine>
            └─ opens /dev/ptmx, runs proot with the pty slave as stdio
```

- **Engine:** `cellar attach <machine> [--cols N --rows N]` — allocate a PTY, start the
  machine's shell under proot with the slave as its controlling terminal, and proxy
  master ↔ stdio. Resize arrives as an escape-prefixed control line on stdin (simplest
  thing that survives a pipe) and becomes a `TIOCSWINSZ` + `SIGWINCH`.
- **App:** one WebView per session, xterm.js rendering, keystrokes back through the
  bridge. No sockets, no ports, no ttyd.
- **Extra keys row** — Esc, Tab, Ctrl, Alt, arrows, `|`, `/`, `-`, `~`, Ctrl-C. A soft
  keyboard cannot type what a terminal needs; Termux's accessory bar is the proven
  pattern and this is the difference between usable and not.
- **Sessions** persist while the machine runs, survive tab switches, and reattach on
  return. Fullscreen is the default posture, not a mode.

**Why not the alternatives:** Termux's terminal-emulator library is GPLv3 (it would
relicense the app); ttyd means another native binary, a build recipe, and a localhost
port; writing an ANSI emulator in Compose is weeks of work to reach parity with a
mature MIT library that already exists.

### 6. API keys are unusable

The current screen asks for a variable name and a blob of text — a developer's mental
model, not a user's. What changes:

- **The terminal makes keys optional for the biggest case.** With a real TTY, Claude
  Code can run its own interactive login inside the machine, exactly as it does on a
  laptop. "Sign in" beats "paste a secret".
- For stacks that genuinely need a key, the app asks **when installing that stack**, by
  name ("OpenCode needs an Anthropic API key"), with paste-from-clipboard, a masked
  field, and a link to where the key comes from.
- The setup tab keeps a plain list of saved keys — the place you go to *revoke*, not the
  place you're forced to start.

## Sequence

| # | step | why this order |
|---|---|---|
| 1 | Quiet, honest stacks + install verdict + log strip cap | small, fixes three reported problems immediately |
| 2 | `cellar attach` in the engine, verified from the CLI | the risky part, provable without the app |
| 3 | xterm.js WebView + bridge + extra keys | the terminal itself |
| 4 | Terminal-first flows: after create, and per stack | what the terminal unlocks |
| 5 | `cellar installed --json` + catalog install-state | needs a machine to query, and a terminal to send you to |
| 6 | Key prompts at install time; login-in-terminal path | last, because the terminal changes what's needed |
